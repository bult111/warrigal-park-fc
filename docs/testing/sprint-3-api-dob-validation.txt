NOTE ON STATUS CODES
--------------------
The task said not to assume every input must return the same status code. These
codes were observed, not assumed: 200 for a successful create (the app redirects
to the new member page), 400 for every rejected create. That matches the
existing route behaviour (routes.member_new returns 400 with the form
re-rendered and a flash message).

WHAT THIS DOES NOT PROVE
------------------------
This is not browser evidence. It shows that the server refuses invalid dates
when a request reaches it. The browser's own date control behaviour is covered
separately in the E2E checklist.
